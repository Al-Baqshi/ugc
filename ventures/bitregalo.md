# BitRegalo

## One-liner
Infrastructure a platform connects to so its records can't be edited afterwards by anyone (its own developers included) and its payment commitments execute exactly as agreed. https://www.bitregalo.com

## Audience
- Platforms that take payments: marketplaces, enterprise systems, banks, startups; their founders, product leads and developers.
- Also: organisations that want their own workspace (contracts, tokens, shop); anyone trying the reference app with practice tokens.

## Pains (from the site's own comparison)
- Records are rows in a database the operator controls; any developer or admin with access can change them.
- A refund is decided by the party that gains when it is refused.
- If the servers go down, records and payments wait on the operator.

## Value props (from bitregalo.com, 2026-10-13)
- Records written once to public contracts; no function exists to edit or delete one, not even for BitRegalo.
- A held payment has only three outcomes: released (buyer), handed back (supplier), returned after the deadline (anyone can trigger). Nobody can send it anywhere else.
- BitRegalo never holds anyone's tokens. Connect the platform you already run; or run a workspace; or use the public BitRegalo network.

## MUST say (honesty, site wording)
- Runs on BNB Smart Chain Testnet (a public test network, tokens have no value); not on a main network.
- Not independently audited; nothing of real value should pass through it yet.
- Examples on the site are illustrations, not customers.
